# 全站 100vh、共用 Navbar 與直向遊玩規範

更新日期：2026-10-26。

本文件是所有現有與未來畫面的共用 UI 規範。「不得超過一個視窗高度」適用全站，包含登入、遊戲選單、遊戲盤面、帳戶、歷史、規則、所有彈窗與大獎動畫，沒有頁面例外。共用 navbar 與直向遊玩要求的範圍依下表及方向限制章節。

2026-10-26 已依使用者要求取消登入、帳戶、獨立紀錄與規則文章頁的高度豁免。本次更新為文件規範同步，沒有完成全站畫面重新驗收。共用手機橫向提醒的既有實作與驗證見下方紀錄；不能將本文件視為全站所有調整皆已完成的證明。

## 核心要求與範圍

1. 所有遊戲使用同一個 `AppPageHeader`，統一 navbar 結構、尺寸、位置與操作方式。
2. 所有畫面不得超過 `100vh`：頁面外層固定一個視窗高度，支援時使用 `100dvh` 對齊手機實際可見高度。Navbar、內容、餘額、操作列、padding、border 與 safe-area 全部包含在這個高度內；彈窗與動畫也不得超出可見範圍。
3. 所有遊戲只提供直向遊玩版面；手機與平板橫放時不能繼續操作遊戲，桌面維持置中的直式容器。

## 共用 Navbar

規格來源為 `apps/web/src/components/ui/AppPageHeader.vue` 與 `apps/web/src/styles/ui.css`。各遊戲只傳入標題、返回事件與 `actions` slot，不另建 navbar 或複製返回按鈕。

| 項目     | 統一規格                                                           |
| -------- | ------------------------------------------------------------------ |
| 左側     | 共用返回按鈕，沿用各頁既有返回流程                                 |
| 中央     | 遊戲名稱；百家樂牌桌沿用廳名。標題相對整個遊戲容器水平置中         |
| 右側     | 規則入口放在 `actions` slot；其他必要操作也必須透過相同 slot       |
| 左右留白 | `var(--ui-page-gutter)`，固定 16 個 CSS px，只套一層               |
| 一般尺寸 | 控制項 44px、header 最小高度 52px、標題 20px，沿用共用變數         |
| 短螢幕   | 可用高度不超過 650px 時，沿用共用控制項 36px、header 最小高度 44px |
| 左右欄   | 等寬，依右側實際所需寬度共同預留，避免標題偏移或與按鈕重疊         |
| 副標     | 遊戲 navbar 不增加狀態副標列；倒數、餘額與投注資訊放入內容區       |
| 主題     | 可沿用各遊戲配色；結構、尺寸、留白與對齊必須一致                   |

- 滿寬場景頁只在 header 設定水平留白；已在頁面設定留白時，header 不再重複加入。
- 不使用 `translate`、負 margin 或單頁箭頭偏移補償對齊問題；先檢查外層留白、共用 grid 與 mobile-forever 轉換。
- 新增圖示使用 `AppIcon`，牌面花色使用 `CardSuit`；共用返回按鈕沿用 `AppPageHeader` 既有 SVG。禁止 emoji、顏文字或一般文字字元充當 UI 圖示。
- 保留 accessible label、鍵盤操作、選取、停用與按下狀態；遵循現有共用 UI 的 hover／focus 規範。
- 沙海神殿右側維持只有規則，不因統一 navbar 恢復已移除的音效按鈕。

## 固定一個視窗高度

所有頁面外層使用固定 `height`，不能只設定 `min-height: 100vh` 後任由內容撐高。Navbar 位於頁面高度之內，不能形成「100vh 內容＋額外 navbar」。`html`、`body`、`#app` 與頁面容器的尺寸及 overflow 須一起檢查，避免任一層產生整頁捲動。

以下是共用容器的結構示意，不代表已新增同名 component 或 CSS class：

```css
.game-page {
  box-sizing: border-box;
  height: 100vh;
  height: 100dvh;
  min-height: 0;
  width: 100%;
  max-width: 430px;
  margin-inline: auto;
  padding-block: env(safe-area-inset-top, 0px) env(safe-area-inset-bottom, 0px);
  display: grid;
  grid-template-rows: auto minmax(0, 1fr) auto;
  overflow: hidden;
}

.game-content {
  min-width: 0;
  min-height: 0;
}
```

三列依序容納 navbar、遊戲內容、餘額與主要操作區。實際可依遊戲結構拆分，但總高度必須一致。上述共用尺寸須避免 mobile-forever 二次縮放；實作前檢查 `apps/web/vite.config.ts`，不要將示意 CSS 直接複製到會轉換的 scoped style。

- 所有頁面與狀態下，整頁不出現水平或垂直捲軸；遊戲的盤面、餘額、投注額與主要操作同時可見。
- 高度不足時先縮減裝飾區與空隙，再依共用短螢幕規格調整尺寸，盤面依可用空間等比例縮放。
- `overflow: hidden` 只負責容器邊界，不能靠裁掉下注按鈕、餘額、牌面或盤面邊緣來通過驗收。
- 登入表單、帳戶、規則、紀錄、牌序與長列表可在各自明確界定的區域捲動；捲動不應帶動整個頁面。彈窗保留可見的關閉入口。
- safe-area 算在既定高度內，不能額外撐高頁面；瀏覽器工具列展開／收合後仍需完整顯示主要操作。
- 載入、等待回覆、錯誤、斷線與動畫期間維持容器尺寸，避免整個版面跳動；錯誤訊息不能在既定高度外新增一列。
- 登入鍵盤開啟時，以 `visualViewport.height`／`offsetTop` 縮小並對齊表單可見區域，不支援時沿用 `innerHeight`；必要時捲動內部表單，聚焦欄位與提交操作須可到達。不能只以 `100dvh` 假設鍵盤已被扣除，也不能裁掉必要操作。
- 路由切換後仍遵守相同高度上限；登入專用的鍵盤定位與監聽須正常清理，不影響其他頁面。

## 所有彈窗與大獎提示

- Big Win／Mega Win／Super Win、免費回合開始與完成提示、遊戲選單、設定、規則、錯誤與確認視窗均不得超過一個可見視窗高度，不能因為使用 `dialog`、Teleport 或 top layer 而豁免。
- 遮罩外層覆蓋可見範圍，卡片的最大高度須扣除上下間距與 safe-area；`box-sizing: border-box` 必須包含 padding 與 border，不能再疊加額外高度。
- 標題、完整獎金數字、關閉／繼續／返回等主要按鈕須留在可見範圍。大金額、長文案或短螢幕下先調整留白、字級與裝飾比例，不能只用 `overflow: hidden` 把內容裁掉。
- Big Win 的文字縮放、金幣、光環、光痕等特效限制在既定動畫容器內，不撐高頁面、不造成外層捲動；動畫最大縮放時也須檢查文字與按鈕是否完整可見。
- 長規則與設定項目只捲動彈窗內的內容區，關閉入口與主要操作保留可見；開啟、關閉、自動消失及切換提示時均不得改變底層頁面高度。

## 只允許直向遊玩

### 手機與平板

- 裝置直向時顯示完整遊戲；橫向時以共用提示覆蓋遊戲，文案為「請將裝置轉為直向遊玩」，保留返回入口。
- 提示顯示時，下層遊戲不可透過觸控、滑鼠或鍵盤觸發操作；停止排程新的付費自動投注與免費自動回合。
- 已送出的請求仍須依原 idempotency key 完成確認與結算；server 的牌局與倒數持續運作。旋轉裝置不取消已接受的投注、不重新抽取結果，也不重設免費進度。
- 回到直向後恢復最新盤面與餘額；付費自動投注維持停止，未完成的免費系列保留並可手動繼續。
- 規則、設定或大獎彈窗開啟時旋轉，也須保持同一套方向限制；回到直向後不能產生重疊彈窗、重複 timer 或重複請求。
- 直向裝置開啟軟鍵盤不能被誤判為橫向；必要輸入框仍須可見。
- 不提供橫向專用盤面，不旋轉整個 DOM 假裝直向，也不要求使用者開啟全螢幕才能滿足方向限制。

### 桌面與寬螢幕

- 桌面可以在寬螢幕瀏覽器內遊玩，但遊戲本體必須保持置中的直式版面，最大寬度沿用 430px；兩側為共用外背景。
- 不因 viewport 寬度大於高度就把桌面改成橫向遊戲；裝置橫放與桌面寬視窗需分開處理。
- 縮短視窗時，遊戲容器寬度可隨高度再縮小以維持直式版面。空間確實不足以完整操作時顯示調整視窗提示，不允許必要控制項溢出或被裁切。
- 既有 `compactLandscape` 或橫向 media query 不作為遊戲橫向玩法的例外，套用本規範時需檢查並移除相應遊戲頁的橫向分支。

## 驗收條件

下列為完整規範的驗收要求；本次已執行的測試及真機驗證限制見「已實作：共用手機橫向提醒」。

| 情境         | 尺寸或條件                                                 | 必須符合                                         |
| ------------ | ---------------------------------------------------------- | ------------------------------------------------ |
| 小型直向手機 | 320×568                                                    | navbar、餘額、盤面與主要按鈕完整可見             |
| 一般直向手機 | 390×844                                                    | 單一視窗高度、無整頁捲動、標題置中               |
| 其他直向尺寸 | 483×771、549×761                                           | 同一套對齊與直式布局，無溢出                     |
| 手機橫向     | 568×320、844×390、771×483，使用手機裝置環境                | 顯示旋轉提示，下層不能操作，沒有新自動投注       |
| 桌面寬視窗   | 1440×900，使用桌面裝置環境                                 | 直式遊戲容器置中，不能切換橫向盤面               |
| 高度變動     | 手機工具列、safe-area、軟鍵盤、桌面縮放視窗                | 必要內容可見，方向判斷正確                       |
| 流程中旋轉   | 延遲回覆、斷線、動畫、自動模式、免費系列                   | 原請求正常確認，資料不丟失、不重複結算           |
| 輔助操作     | Tab／Enter／Esc、reduced motion                            | 方向提示與彈窗可操作，受遮擋遊戲無法取得操作焦點 |
| 非遊戲頁     | 登入、帳戶、歷史、獨立規則頁；短螢幕及長內容               | 外層不超過可見高度，只允許指定內容區內部捲動     |
| 登入鍵盤     | 帳號／密碼聚焦、鍵盤開啟／收起、登入錯誤訊息               | 表單可見區依鍵盤縮小，聚焦欄位及提交操作可到達   |
| 所有彈窗     | 遊戲選單、規則、設定、確認、錯誤、免費開始／完成           | 卡片、關閉入口與主要操作均在可見高度內           |
| 大獎動畫     | Big Win／Mega Win／Super Win、最大獎金位數、動畫最大縮放時 | 標題、獎金與操作不被裁切，粒子不產生整頁溢出     |

跨頁比對所有 navbar 的返回按鈕、標題與右側操作的實際位置。允許渲染取整差異，但不接受用單頁位移掩蓋差異。Chromium 與 WebKit 均需驗證；手機工具列、鍵盤與旋轉行為另需真機檢查。

高度驗收須同時檢查 document 是否溢出，以及頁面／彈窗外框、標題與必要操作的實際 bounding box 是否落在可見視窗內（鍵盤開啟時使用 visual viewport）。只有 `scrollHeight` 沒有增加，或只設定 `overflow: hidden`，都不足以證明通過。動畫須涵蓋開始、最大伸展與結束狀態。

`e2e/viewport.spec.ts` 包含共用 header 對齊與全部遊戲／大廳的橫向提醒，`e2e/storm-portrait-mocked.spec.ts` 涵蓋沙海神殿直式布局，`e2e/portrait-guard-mocked.spec.ts` 驗證共用提醒的互動。這些測試不取代所有遊戲狀態與真機旋轉的完整驗收。

## 已實作：共用手機橫向提醒

2026-10-25 已將 `PortraitGuard.vue` 接到 `App.vue`，由路由 `meta.portraitOnly` 決定是否啟用，覆蓋上方六款遊戲、遊戲大廳與百家樂選桌。登入、帳戶、歷史與獨立規則文章頁不啟用。

- 透過 `usePortraitGuard.ts` 共用方向狀態，識別 iPhone、Android 與 iPad（含使用桌面 UA 的 iPadOS）。一般桌面寬視窗維持原本版面。
- 優先讀取 [ScreenOrientation.type](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/type)，再使用舊版方向角度或實體螢幕尺寸作為 fallback，不使用軟鍵盤縮小後的頁面高度判斷裝置方向。
- 使用原生 [`dialog.showModal()`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/showModal) 的 top layer 覆蓋既有規則／設定視窗，阻擋下層點擊與鍵盤操作。Esc 不關閉方向提醒；遊戲頁保留返回大廳按鈕，大廳本身只顯示提示。
- 提示使用既有 `AppIcon` 的 `rotate` font icon，沒有 emoji、文字圖示或外部圖片。滿版樣式排除 mobile-forever 的尺寸轉換。
- 回到直向時自動關閉提醒，遊戲 component 不卸載；原盤面、設定與已開啟的規則視窗保留。
- Plinko 停止後續自動投球；沙海神殿停止付費／免費自動回合並取消免費開始倒數。進行中的回覆正常接收與結算，已有未確認操作仍沿用原請求確認。轉回直向不自動恢復投注或免費倒數，玩家可手動繼續。
- 離開或卸載時清理方向、resize 與 pageshow 監聽。

驗證：75 項 component／composable tests 通過，涵蓋手機／桌面／iPadOS、舊 API fallback、鍵盤不誤判、監聽清理、延遲回覆結算、自動停止及免費倒數停止；Chromium／WebKit 合計 42 項 E2E 通過，包含全部遊戲路由、滿版提醒、既有彈窗覆蓋、Esc／Tab、轉回後保留盤面、返回大廳與原 viewport regression。web typecheck、變更程式 ESLint 與 E2E TypeScript 檢查通過。

E2E 的方向切換透過瀏覽器 API 模擬，所有投注使用 mocked transport。實際 iPhone／Android 的旋轉、瀏覽器工具列與鍵盤仍需真機驗證；本次沒有操作玩家錢包或修改 server 遊戲規則。

```sh
npm exec --workspace web -- vitest run src/composables/usePortraitGuard.test.ts src/views/StormDemoView.test.ts src/views/PlinkoView.test.ts
E2E_MOCKED_ONLY=true npm run test:e2e -- e2e/portrait-guard-mocked.spec.ts e2e/viewport.spec.ts e2e/storm-portrait-mocked.spec.ts
```
