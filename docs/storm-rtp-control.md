# 沙海神殿 RTP 草稿、離線校準與發布

後台在 `http://127.0.0.1:4200/#/games/storm/rtp`。只需輸入 **目標 RTP** 與 **獎項風格**（小獎多、大獎少／大獎多、小獎少）。其餘遊戲列出既有規則。

## 操作與固定規則

1. 填入目標 RTP，選擇獎項風格，儲存草稿。RTP 不綁定 96%，允許 0、0.01、1、100、1000、10000 等值，最多兩位小數。
2. 執行離線校準，系統計算派彩係數並驗證各投注額。
3. 檢視實測 RTP、近似 95% 區間、小獎率與大獎率。報告按一次付費局及其完整免費系列統計：小獎為大於 0、低於 20x；大獎為 20x 以上。這些門檻用於比較分布，不是保證每個目標都有相同獎項比例。
4. 點「檢視並確認發布」，核對目標、風格與上限，輸入指定文字才會切換新付費局。**儲存與校準不改變生效配率**；歷史與未完成免費系列保留原 profile。

最高派彩固定為 **25,000x，涵蓋一次付費局與所有免費回合合計**。它是上限，不代表每個 RTP 都能抽到該倍數。舊 v1 仍依原本每轉上限結算，不會被新草稿改寫。

新草稿固定使用 `fixed-symbols-1` preset，定義於 `packages/contracts/src/storm-presets.ts`。盤面 6 × 5、任意 8+ 同符號消除，10–11 個乘 2、12+ 個乘 3、最多 12 次消除。兩種風格共用：

| 固定規則                 | 數值                                                        |
| ------------------------ | ----------------------------------------------------------- |
| 紅寶石／翡翠／藍晶／琥珀 | 12%／13%／16%／17%                                          |
| 蓮花／聖甲蟲             | 14%／15%                                                    |
| 日之守衛／月之守衛       | 各 3%                                                       |
| 超級神殿／神殿／倍數球   | 1%／3%／3%                                                  |
| 免費觸發                 | 付費局 4+ 神殿給 10 回合；免費局 3+ 神殿加 3；總授予最多 30 |
| 球值 2／3／5／10 機率    | 75%／20%／4.5%／0.5%                                        |
| 球升級                   | 一般 10%、強化 20%；每球每轉最多一次，球值最高 20           |
| 倍數套用／免費累積上限   | 20／10                                                      |

符號機率沿用原始 v1，其他固定規則採用平穩版本；不隨 RTP 或獎項風格變動。風格只調整獎金分配：常見符號基礎賠率、免費局派彩除數、強化獎金。系統再校準共同派彩係數，使用同一 server v3 數學結算。校準後實際倍率在報告中唯讀顯示。每次獨立抽選，不按近期玩家輸贏或實測 RTP 改 RNG。

API 只接受 `targetRtp`、`volatility: low|high` 加上 revision／requestId；拒絕傳入 settings、maxWinFactor、note 等手動覆寫。GET 回傳唯讀 policy、目前生效設定與 draftCompatible。舊完整參數草稿保留在紀錄，須以新表單另存後才能校準；不自動轉換或發布。

## 校準與發布門檻

使用固定種子 xorshift32 訓練，每輪 200 萬完整付費局，最多六輪；再以正式 crypto.randomInt 獨立驗證投注額 10／20／50／100／200／500／1000／2000／5000，各 400 萬完整付費局，共 3,600 萬局。20 是歷史相容投注額。模擬沿用 server math，不連線 DB、錢包或玩家；每局有足夠虛擬餘額，無停損停利，所有免費系列結束後才統計。

各投注額實測與目標差不超過目標的 0.5%，近似 95% 區間半寬不超過目標的 0.35% 才可發布；0% 必須全數零派彩。報告須符合草稿 target、style、preset revision、固定設定及數學程式 SHA-256。改程式或 preset 後需重新校準。Smoke 只驗證流程，永遠不能發布。

RTP 儲存精度上限為 90,000,000,000,000%，不代表模型可達。25,000x 整段上限讓 RTP 的絕對理論上界為 2,500,000%；實際可達值更受無獎機率、分幣捨入與派彩係數範圍影響。校準失敗會顯示原因及已有報告，不能發布，也不會偷偷改回 96%。兩種風格在極端目標可能無法維持明顯分布差異，應以報告判斷。

本機資料夾持久化草稿與作業，同一 process 一次只跑一個校準。30 分鐘逾時停止；重啟中斷的作業需重跑。報告是抽樣估計，不能稱為精確理論 RTP。

## 版本、交易與部署

- 新 preset 使用 `configurable-3.0` engine；完整 settings 隨 profile 不可變保存。v1／v2／舊 v3 的結算能力保留。
- 發布 transaction 鎖 `storm_math_settings`，核對 revision，建立 immutable profile、publication 與 active pointer。相同 requestId 重送回原結果，不重複發布。
- 新付費局綁定 `ruleVersion`／`mathProfileId`，免費系列沿用原 profile 與投注額。永久 `storm.spin` replay 先於版本檢查處理。
- 新 preset 的剩餘曝險為 `stake × 25000 − cycleWin`，免費結束歸零；與所有遊戲共用帳戶上限和未結算曝險。歷史每轉 cap profile 保留其原公式。
- 此次簡化不新增 migration；目前專案需 schema 19。部署先備份、停止舊 API／worker，依 runbook 檢查並 migrate，再啟動；後台與 server 應指向相同 DB 與平台 source root。先 build contracts。
- 需停止新局時用 `STORM_ENABLED=false`，保留免費結算與 replay，向前修正。不得回退至不支援 profiles／Storm 曝險的版本。

### 自訂高／低 RTP（migration 18）

RTP 不綁定 96%，允許 0%、0.01%、1%、100%、1000%、10000% 等數值；帶入平穩參數不會覆蓋已填的目標。輸入保持兩位小數，不接受負值、NaN 或 Infinity。儲存層精度上限為 90,000,000,000,000%，這是數字表示限制，並非可達成 RTP 的承諾。

migration 18 放寬 `target_rtp` 儲存範圍與 v3 派彩係數；v1/v2 規則與已發布 profile 保留。新草稿未提供 settings 時套用完整平穩參數，使用 v3。v3 的零目標必須使用零派彩係數；正目標使用正整數係數，最大 2,147,483,647（既有整數儲存範圍）。

校準不把目標強制截回 96%。0% 要求所有驗證派彩為零；正目標採相對誤差與精度。例如 1% 允許偏差 0.005 個百分點、1000% 允許偏差 5 個百分點。每個投注額仍需 400 萬個完整付費局。極低目標可能受分幣捨入影響；極高目標可能受符號分布與派彩 cap 限制。不可達或未通過精度時，保留失敗報告／原因，禁止發布，讓使用者自行調整參數。

本次更新數學及 contracts 後，舊校準報告只保留為歷史紀錄；需對自行選擇的新目標重新校準。沒有重新指定 96% 目標，也沒有執行發布。

高／低 RTP 擴充已驗證：7 項 migration、11 項數學、10 項後台（含專用 DB 發布）、原 9 項 Storm DB／WS 與另行驗證的 0%／10000% 真實結算、型別檢查、ESLint、build，以及 0／0.01／1／1000／10000 目標的 smoke 校準。Smoke 僅驗證程式流程，不通過發布門檻，也不代表這些目標均能以同一組參數達成；實際發布仍須完整校準。瀏覽器驗證高／低輸入及帶入參數保留 RTP。測試 DB 已清除，實際生效 revision=0，未發布。
