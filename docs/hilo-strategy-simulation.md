# Hi-Lo：A／2／3 猜大、J／Q／K 猜小，100 萬局模擬

執行時間：2026-09-17；此次實測 RTP **93.63690976%**。

## 策略與假設

- 次數指 1,000,000 個獨立牌局，不是 1,000,000 次單步猜牌。
- 每局下注 100 幣，沒有本金不足停止或加減碼。
- 下注前免費換牌，直到起始牌為 A／2／3／J／Q／K。
- A 猜嚴格更高；2／3 猜大於或等於；J／Q 猜小於或等於；K 猜嚴格更低。
- 局中 4～10 一律跳牌。猜錯派彩為零；精確含本金倍率嚴格大於 50 時收款。
- 沿用現有每局 52 次跳牌限制：用完後，若目前牌仍有策略選項則繼續猜；若沒有策略選項則提早收款。這是模擬的策略補充，並非 server 強制在 52 次後自動收款。
- 先挑選策略內的起始牌，所以仍存活的局必定已猜對至少一次，跳牌用完時皆可收款，沒有未完成局。
- 直接引用 server 的 `crypto.randomInt(52)` 抽牌、勝負判斷、BigInt 有理數倍率與分幣 ROUND_HALF_UP 派彩。每次獨立、有放回；只在首次倍率套用一次 0.94。
- 僅記憶體內模擬，不呼叫投注 API、不寫入資料庫或錢包。

實測 RTP = 總派彩 ÷ 總投注。每局取整前的理論 RTP 仍為 94%，挑牌策略改變勝率、收款分布與波動，不改變這套賠率的期望回報。

以各局派彩的樣本變異數估計，此次 RTP 的標準誤約 0.66694 個百分點，常態近似 95% 區間約 92.3297%～94.9441%。93.6369% 是單次亂數樣本結果，不能視為新設定的 RTP，也不是未來回報保證。使用 crypto RNG，每次重跑的數字會不同。

## 重跑

從 repository 根目錄執行：

```sh
npx tsx --test apps/server/src/lib/hilo-strategy-simulation.test.ts apps/server/src/lib/hilo.test.ts
npx tsx apps/server/src/scripts/simulate-hilo-strategy.ts 1000000
```

原始結果保存在 `docs/hilo-strategy-simulation-result.json`，金額欄位以分幣整數字串保存。

驗證：8 項策略與現有 Hi-Lo 數學測試通過；server typecheck、新增 TypeScript 的 ESLint 與 diff whitespace 檢查通過。模擬不以隨機 RTP 必須命中固定區間作為測試通過條件。
